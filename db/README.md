## Исходная база данных

`cadr_reserve.sql` и `cadr_reserve_schema.sql` — выгрузки исходной базы
`cadr_reserve`. Файлы включены без изменений: они служат исходным
материалом и одновременно доказательством того, что перенос данных выполнен
из настоящего источника, а не из придуманного набора.

Состав исходных данных:

| Таблица | Строк |
|---|---|
| `branch` | 4 |
| `department` | 18 |
| `User` | 43 |
| `candidate` | 40 |
| `reserve` | 39 |
| `reservestatushistory` | 45 |
| `assessment` | 85 |
| `developmentplan` | 39 |
| `developmentactivity` | 115 |
| **Итого** | **428** |

Перенос выполняется командой `import_legacy`. Все 428 строк переносятся без
потерь; выявленные дефекты исходных данных (незаполненная привязка к
подразделению у 23 карточек, 66 выполненных мероприятий без даты выполнения)
устраняются с выводом отчёта — подробности в документации команды.

## Схема системы

`schema.sql` выгружается из работающей базы после применения миграций:

```bash
pg_dump -h localhost -U reservix -d reservix --schema-only --no-owner --no-privileges -f db/schema.sql
```

Файл отражает состояние схемы на момент выгрузки и обновляется при изменении
модели. Источником истины остаются миграции Django: схема воспроизводится
командой `migrate`, а выгрузка приложена для чтения и проверки без запуска
приложения.

## Демонстрационные данные

`demo_data.sql` — полная копия демонстрационного стенда после `seed_demo`:
схема, данные всех разделов, английские версии справочников и содержимого.
Разворачивается в пустую базу без предварительных миграций:

```bash
createdb -h localhost -U reservix reservix
psql -h localhost -U reservix -d reservix -f db/demo_data.sql
```

Тот же результат воспроизводится без файла — последовательностью команд:

```bash
uv run python manage.py migrate
uv run python manage.py seed_demo --seed 42
```

Второй способ предпочтителен: он проверяет работоспособность самих команд
наполнения, а не только восстановление снимка.
